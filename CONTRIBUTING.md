# Contributing to DDKLab

## Before contributing

- Keep the project browser-first and local-first.
- Do not commit identifiable participant data or clinical recordings.
- Preserve the human-verification boundary for automatic DDK measurements.
- Do not present synthetic or software-test results as clinical validation.

## Development

1. Create a focused branch.
2. Make one logical change at a time.
3. Run the repository quality checks.
4. Update documentation when behavior changes.
5. Explain validation evidence and known limitations in the pull request.

For algorithm changes, document the DSP version, parameters, expected behavior, and validation impact.
